# 代码目录与职责

代码按功能分组，子目录根据实际职责建立。文件夹不等于独立运行系统，也不要求每个目录创建 Manager。

```text
Assets/
├── Scripts/
│   ├── ScenarioSystem/
│   │   ├── Data/       关卡定义、情境配置
│   │   └── Runtime/    会话、流程控制、行为记录
│   ├── EmailSystem/
│   │   ├── Data/       发件人、邮件正文等内容类型
│   │   └── UI/         收件箱和邮件展示
│   ├── VerifySystem/
│   │   ├── Data/       浏览器页面、可信入口与外部请求内容
│   │   └── UI/         Browser、通用信息页，Portal 是其中一页
│   ├── EvidenceSystem/
│   │   ├── Data/       证据内容类型
│   │   ├── Runtime/    当前证据状态与收集逻辑
│   │   └── UI/         证据收集按钮和摘要展示
│   ├── ResponseSystem/
│   │   ├── Data/       回应类型、可选后续处理配置
│   │   ├── Runtime/    回应操作与处理逻辑
│   │   └── UI/         回应操作和后续处理选择
│   ├── FeedbackSystem/
│   │   ├── Data/       固定分支反馈文案、只读评估结果
│   │   ├── Runtime/    决策评估器
│   │   └── UI/         结果与反馈展示
│   ├── TutorialSystem/
│   │   ├── Data/       教程步骤、完成条件与 UI 目标配置
│   │   ├── Runtime/    独立教程流程，读取现有会话与行为记录
│   │   └── UI/         文字提示、聚焦遮罩与临时输入限制
│   └── UI/
│       └── Runtime/    公共窗口管理和现有按钮脚本
├── Prefabs/
│   └── UI/
│       └── Evidence/
│           └── EvidenceSpot.prefab  可复用的关键内容卡片
└── Data/
    ├── Scenarios/         实际关卡配置资产（.asset）
    ├── VerificationPages/ 可被关卡引用的浏览器页面内容（.asset）
    └── Evidence/          可被关卡引用的证据内容（.asset）
```

## 放置约定

- `Data` 存放 C# 数据定义，不负责打开窗口或推进流程。
- `Runtime` 存放运行逻辑。纯 C# 逻辑无需为挂载到场景而继承 MonoBehaviour。
- 模块内的 `UI` 存放该功能的界面脚本。公共窗口与导航脚本放在 `Scripts/UI/Runtime`。
- ScriptableObject 的类型定义放在对应功能的 `Data`，实际内容资产按类型放在 `Assets/Data/Scenarios`、`Assets/Data/VerificationPages` 等目录。
- 玩家进度归 ScenarioSession 所有，不能写回关卡配置资产；界面只显示数据、提交操作。
- 已有 EvidenceSystem、ResponseSystem 初版脚本放在各自的 Runtime，保留供旧场景使用。Scenario 的进度、证据 ID、提醒状态和决策快照归 ScenarioSession 所有，操作通过 ScenarioController 提交。
- 暂不添加程序集定义、额外框架、空类或尚未使用的模块。新增交互需求出现时再增加相应目录。
- `.gitkeep` 保留空的预留目录；目录开始包含实际文件后可以删除该占位文件。

## UI 方法职责

- `Refresh()` 接收状态变化后组织更新步骤；正文、入口、通知、显隐和滚动分别交给对应方法。
- `RefreshContent()` 等内容方法负责文字和数据显示，不承担最终选择或关卡推进。
- `SetVisible(bool)` 根据会话状态分派显隐；各主要 View 的 `Show()`、`Hide()` 是明确的表现入口，重复设置同一状态不会再次开关窗口。
- `Show()`、`Hide()` 只控制界面，不改变 ScenarioSession。玩家打开邮件、关闭笔记、结束回应等操作调用 ScenarioController，再由状态通知 View 同步表现。
- 浏览器的 `ShowHomePage()`、`ShowInformationPage()` 管理首页与信息页显示；页面文字、导航、证据卡片和滚动分别处理。
- `ResetScroll()`、`ResetScrollIfNeeded()` 负责布局完成后的阅读位置；普通状态刷新不重置同一页面的阅读位置。
- 窗口动效、开关音效接入对应 View 的显隐方法；异步关闭动画应完成后再停用窗口，并由动效组件管理重复播放或中断。

所有场景和玩法设置均可在Scenario data中完成，完全可复用。

## 浏览器链接与请求页面

- `EmailScenarioDefinition.VerificationPages` 是浏览器主页的可信入口；`LinkedPages` 是正文链接能访问的额外页面，不占用主页入口。
- 页面 `Address` 对应文案中的完整 HTTP/HTTPS 网址；本关每个地址和页面 ID 应唯一。链接只匹配本关内容，不打开真实网站。未配置的地址会输出警告，编辑新链接时需同步关联页面资产。
- 邮件的 `ProceedLink` 可指定继续操作要访问的网址；留空沿用直接 Proceed 结算。正文链接和邮件 Proceed 统一调用 `ScenarioController.OpenLink()`。
- 页面 `IsUnsafe` 是设计者配置的风险标记，不在游玩 UI 暴露真假。风险页面复用同一浏览器信息页，通过 `ProcessLabel` 描述提交操作。
- `BrowserAppView` 的 `processPanel`、`processButton`、`processText` 绑定浏览器内容下的 `RequestActions`；`ShowProcessAction()`、`HideProcessAction()` 管理显隐，提交调用 `ScenarioController.SubmitBrowserInformation()`。
- `BrowserLinkText.SetText()` 首次绑定时在现有 TMP 对象上添加点击组件；正文按普通文字转义，只为识别到的网址生成高亮、下划线与链接。无须为每条链接新增按钮或窗口。
- `ScenarioSession.History` 的 `UnsafeLinkOpened` 与 `InformationSubmitted` 分别记录打开风险页面、提交资料。点击不自动结束；提交才按 Proceed 结算。风险点击次数与证据一样在决定时冻结，保存于 `ScenarioEvaluation`。
- `ScenarioFeedbackConfig.UnsafeLinkWarning` 配置点击风险链接后未提交的补充文案，支持 `{unsafeLinkCount}`；这是一条固定反馈，没有通用规则引擎或独立追踪 Manager。

## 教程配置与界面

- `TutorialFlow` 仅挂在需要引导的场景中；`controller` 引用现有 ScenarioController，`overlay` 引用教程界面，`evidenceContainer` 引用浏览器生成卡片的 Content。
- `steps` 在场景 Inspector 中编辑，不需要额外 ScriptableObject 资产。`Next` 由提示框按钮推进；`ScenarioEvent` 匹配当前步骤开始之后的事件及可选 `targetId`；`ReminderClosed`、`SummaryClosed` 读取已有窗口状态。
- `focusTarget` 是亮起的区域；`interactionTarget` 是允许点击的目标，留空使用聚焦目标。`scrollArea` 绑定 ScrollRect 的 Viewport，阅读步骤只转发滚动，不放行区域内的链接和按钮。
- `focusEvidence` 根据 `targetId` 在当前页绑定动态证据卡片；对应关系使用当前页面 EvidencePlacements 的生成顺序，查找范围限定为 `evidenceContainer`。调整卡片生成顺序时应同步此绑定逻辑。
- `Prefabs/UI/Tutorial/TutorialUI.prefab` 不含 Canvas，作为既有 Canvas 的子对象使用。其结构为 `Overlay/InputBlocker`、`Dimmer`、`FocusFrame`、`GuidePanel`；Overlay 初始隐藏，界面脚本常驻。
- `TutorialOverlayView.ShowStep()` 更新提示、聚焦与输入状态；`Hide()` 隐藏全部引导并恢复进入教程前的 EventSystem 导航设置。`blockInput` 为 false 的步骤保留文字提示，解除外围遮罩和点击限制。
- TutorialFlow 只读取 ScenarioSession，不调用打开邮件、保存证据或选择回应等玩法操作。`hasStarted` 独立于 Session 保存，首次开始后 Reset/Play again 不再教学；重新载入场景创建新的 TutorialFlow 时可再次引导，未增加持久存档。
- `ShowSkipConfirmation()` 复用 GuidePanel 显示跳过确认，并临时拦截全部玩法操作；`CancelSkipConfirmation()` 恢复当前提示、聚焦与原有输入限制。只有确认按钮触发 SkipRequested，结算或重置时一并隐藏确认框。
