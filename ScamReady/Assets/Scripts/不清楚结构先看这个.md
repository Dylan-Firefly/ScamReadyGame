# 代码目录与职责

代码按功能分组，子目录根据实际职责建立。文件夹不等于独立运行系统，也不要求每个目录创建 Manager。

```text
Assets/
├── Scripts/
│   ├── ScenarioSystem/
│   │   ├── Data/       关卡定义、情境配置
│   │   └── Runtime/    会话、流程控制、行为记录
│   ├── EmailSystem/
│   │   ├── Data/       发件人、邮件正文等内容类型
│   │   └── UI/         收件箱和邮件展示
│   ├── VerifySystem/
│   │   ├── Data/       查验页面和可信入口类型
│   │   └── UI/         Browser、通用信息页，Portal 是其中一页
│   ├── EvidenceSystem/
│   │   ├── Data/       证据内容类型
│   │   ├── Runtime/    当前证据状态与收集逻辑
│   │   └── UI/         证据收集按钮和摘要展示
│   ├── ResponseSystem/
│   │   ├── Data/       回应类型、可选后续处理配置
│   │   ├── Runtime/    回应操作与处理逻辑
│   │   └── UI/         回应操作和后续处理选择
│   ├── FeedbackSystem/
│   │   ├── Data/       固定分支反馈文案、只读评估结果
│   │   ├── Runtime/    决策评估器
│   │   └── UI/         结果与反馈展示
│   └── UI/
│       └── Runtime/    公共窗口管理和现有按钮脚本
├── Prefabs/
│   └── UI/
│       └── Evidence/
│           └── EvidenceSpot.prefab  可复用的关键内容卡片
└── Data/
    ├── Scenarios/         实际关卡配置资产（.asset）
    ├── VerificationPages/ 可被关卡引用的官网页面内容（.asset）
    └── Evidence/          可被关卡引用的证据内容（.asset）
```

## 放置约定

- `Data` 存放 C# 数据定义，不负责打开窗口或推进流程。
- `Runtime` 存放运行逻辑。纯 C# 逻辑无需为挂载到场景而继承 MonoBehaviour。
- 模块内的 `UI` 存放该功能的界面脚本。公共窗口与导航脚本放在 `Scripts/UI/Runtime`。
- ScriptableObject 的类型定义放在对应功能的 `Data`，实际内容资产按类型放在 `Assets/Data/Scenarios`、`Assets/Data/VerificationPages` 等目录。
- 玩家进度归 ScenarioSession 所有，不能写回关卡配置资产；界面只显示数据、提交操作。
- 已有 EvidenceSystem、ResponseSystem 初版脚本放在各自的 Runtime，保留供旧场景使用。Scenario 的进度、证据 ID、提醒状态和决策快照归 ScenarioSession 所有，操作通过 ScenarioController 提交。
- 暂不添加程序集定义、额外框架、空类或尚未使用的模块。新增交互需求出现时再增加相应目录。
- `.gitkeep` 保留空的预留目录；目录开始包含实际文件后可以删除该占位文件。

## 当前系统脚本

| 脚本 | 位置 | 当前职责 |
|---|---|---|
| ResponseSystem.cs | ResponseSystem/Runtime | 接收四类回应操作，根据当前证据状态调用反馈 |
| EvidenceSystem.cs | EvidenceSystem/Runtime | 保存证据布尔状态，支持收集、查询和重置 |
| FeedbackSystem.cs | FeedbackSystem/UI | 打开关闭反馈面板，设置标题和正文 |
| VerificationPageDefinition.cs | VerifySystem/Data | 官网入口名称、地址、页面正文与稳定 ID |
| VerificationLinkView.cs | VerifySystem/UI | 展示一个官网入口并提交页面选择 |
| BrowserAppView.cs | VerifySystem/UI | 浏览器导航、首页入口和通用信息页展示 |
| EvidenceDefinition.cs | EvidenceSystem/Data | 证据 ID、标题与事实摘要 |
| EvidencePlacement.cs | EvidenceSystem/Data | 页面、可点击内容与证据的放置关系 |
| EvidenceSpotView.cs | EvidenceSystem/UI | 可复用证据卡片的展示与收集操作 |
| EvidenceSummaryView.cs | EvidenceSystem/UI | 已收集证据的摘要窗口 |
| ReminderConfig.cs | ScenarioSystem/Data | 一次提醒的内容与收集数量条件 |
| ReminderView.cs | UI/Runtime | 提醒通知的显示与关闭 |
| ScenarioFeedbackConfig.cs | FeedbackSystem/Data | 关卡内五种结果分支的标题和正文 |
| ScenarioEvaluation.cs | FeedbackSystem/Data | 决策、结果类型及决策时的证据数量 |
| ScenarioEvaluator.cs | FeedbackSystem/Runtime | 按最终回应和证据快照评估邮件诈骗 |
| ScenarioResultView.cs | FeedbackSystem/UI | 结果窗口展示和重新开始入口 |

旧 FeedbackSystem.cs 保留供成员原有场景使用。Scenario 的纯评估逻辑由 ScenarioEvaluator 承担，冻结结果由 ScenarioController 保存；ScenarioResultView 只负责显示。
