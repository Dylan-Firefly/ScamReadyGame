# 代码目录与职责

代码按功能分组，子目录根据实际职责建立。文件夹不等于独立运行系统，也不要求每个目录创建 Manager。

```text
Assets/
├── Scripts/
│   ├── ScenarioSystem/
│   │   ├── Data/       关卡定义、情境配置
│   │   └── Runtime/    会话、流程控制、行为记录
│   ├── EmailSystem/
│   │   ├── Data/       发件人、邮件正文等内容类型
│   │   └── UI/         收件箱和邮件展示
│   ├── VerifySystem/
│   │   ├── Data/       查验页面和可信入口类型
│   │   └── UI/         Browser、通用信息页，Portal 是其中一页
│   ├── EvidenceSystem/
│   │   ├── Data/       证据内容类型
│   │   └── UI/         证据收集按钮和摘要展示
│   ├── ResponseSystem/
│   │   ├── Data/       回应类型、可选后续处理配置
│   │   └── UI/         回应操作和后续处理选择
│   ├── FeedbackSystem/
│   │   ├── Data/       结果条件、反馈内容、评估结果类型
│   │   ├── Runtime/    决策评估器
│   │   └── UI/         结果与反馈展示
│   └── UI/
│       └── Runtime/    公共窗口管理和现有按钮脚本
└── Data/
    └── Scenarios/      实际关卡配置资产（.asset）
```

## 放置约定

- `Data` 存放 C# 数据定义，不负责打开窗口或推进流程。
- `Runtime` 存放运行逻辑。纯 C# 逻辑无需为挂载到场景而继承 MonoBehaviour。
- 模块内的 `UI` 存放该功能的界面脚本。公共窗口与导航脚本放在 `Scripts/UI/Runtime`。
- ScriptableObject 的类型定义放在对应模块的 `Data`，实际内容资产放在 `Assets/Data/Scenarios`。
- 玩家进度归 ScenarioSession 所有，不能写回关卡配置资产；界面只显示数据、提交操作。
- Evidence 的收集状态和 Response 的流程由 Session/Controller 管理，当前不单独创建它们的 Runtime 或 Manager。
- 暂不添加程序集定义、额外框架、空类或尚未使用的模块。新增交互需求出现时再增加相应目录。
- `.gitkeep` 保留空的预留目录；目录开始包含实际文件后可以删除该占位文件。

## 保留脚本

`UI/Runtime/MainMenuButtonManagement.cs` 是现有面板开关脚本，暂时保持内容、类名和全局命名空间不变。移动时保留原 `.meta` 与 GUID，使场景组件和按钮 UnityEvent 继续引用同一个脚本。

之后接入新窗口逻辑时再决定是否替换它，避免本轮目录整理扩大成业务重构。
